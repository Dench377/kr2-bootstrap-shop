## Краткое описание проекта

В проекте реализован многостраничный HTML/CSS-сайт интернет-магазина аудиотехники и акустических компонентов **«Aura Sound»**. 
Сайт спроектирован на чистом семантическом HTML5 и модульном CSS3 с применением методологии БЭМ, CSS Grid и Flexbox, без использования тяжелых CSS-фреймворков. 
Для модального окна предусмотрена как чистая CSS-реализация (`:target`), так и минимальный вспомогательный скрипт `js/main.js` в соответствии с разделом 3 методических указаний.

Проект является базисом для последующих контрольных работ:
- **КР №3:** Адаптация верстки под мобильные и планшетные устройства (Media Queries);
- **КР №4:** Добавление полноценной JavaScript-интерактивности (фильтрация, корзина, счетчики);
- **КР №5:** Перенос предметной области в SPA на React или Vue.

## Используемые технологии

- **HTML5:** Семантические теги (`header`, `nav`, `main`, `section`, `article`, `aside`, `footer`, `figure`, `time`, `address`, `table`, `form`). На каждой странице строго один тег `main`.
- **CSS3:** 
  - CSS-переменные в блоке `:root` (`--color-primary`, `--color-primary-dark`, `--color-border`, `--color-danger`, `--space-sm`, `--space-md`, `--space-lg`, `--radius-sm`, `--radius-md`);
  - CSS Grid (сетка каталога, раскладка страницы каталога с фильтрами, форма оформления заявки);
  - Flexbox (навигация, выравнивание элементов в шапке, кнопки, карточки товаров);
  - Базовое позиционирование (`relative`, `absolute`, `sticky`, `fixed`, `z-index`);
  - Состояния интерактивных элементов (`:hover`, `:focus-visible`, `:active`, `:disabled`).
- **Методология БЭМ:** Именование классов по схеме Блок-Элемент-Модификатор (`site-header`, `site-nav`, `product-card`, `product-card__title`, `product-card__description`, `product-card__price`, `product-card__button`, `product-card--discount`, `order-form`, `order-form__field`, `order-form__label`, `order-form__input`, `order-form__actions`). Без использования нерекомендуемых антипаттернов (классов `red`, `blue`, `big`, `left`, `right`).
- **JavaScript (минимальный):** Файл `js/main.js` для открытия и закрытия модального окна заявки.
- **Чистота кода:** Исходный код не содержит комментариев в соответствии с установленным требованием к оформлению.

## Описание обязательных страниц

1. **`index.html` (Главная страница):**
   - Hero-блок с призывом к действию и промо-иллюстрацией;
   - Якорные ссылки: `index.html#advantages` (Преимущества), `index.html#popular` (Популярные товары), `index.html#contacts` (Контакты);
   - Секция преимуществ магазина (`id="advantages"`);
   - Сетка популярных товаров с бейджами («Хит», «Новинка», «Скидка»);
   - Блок отзывов клиентов и блок частых вопросов (FAQ);
   - Модальное окно быстрого заказа.
2. **`catalog.html` (Каталог товаров):**
   - Хлебные крошки;
   - Двухколоночный макет (`catalog-layout`): липкий сайдбар с фильтрами (`<aside>`) по категориям, цене, ANC, наличию;
   - Панель сортировки и Grid-сетка из 8 карточек товаров;
   - Пагинация страниц.
3. **`product.html` (Карточка товара):**
   - Хлебные крошки;
   - Детальный блок флагмана: галерея ракурсов, рейтинг, бейдж наличия, акционная и базовая цена, кнопка оформления заявки;
   - Полная семантическая таблица характеристик и сравнения (`table`, `caption`, `thead`, `tbody`, `tfoot`, `th`, `td`) с чередующейся зеброй строк и подсветкой при наведении.
4. **`order.html` (Оформление заявки):**
   - Полноценная форма оформления заявки с полями: Имя, E-mail (`type="email"`), Телефон (`type="tel"`), Выбранный товар (`select`), Комментарий/адрес (`textarea`), Согласие на обработку данных (`checkbox`);
   - Все поля имеют парные `label` с совпадающими `for` и `id`, атрибуты `name` и `required`;
   - Сайдбар с составом заказа, расчетом скидки и итоговой стоимостью.
5. **`contacts.html` (Контакты):**
   - Адрес флагманского шоурума (проспект Вернадского, 78, РТУ МИРЭА), телефоны, email, график работы, банковские реквизиты;
   - Стилизованная схема проезда;
   - Форма обратной связи.

## Инструкция по просмотру и запуску проекта

### 1. Локальный просмотр
Откройте файл `index.html` в любом современном веб-браузере (Google Chrome, Яндекс.Браузер, Mozilla Firefox, Microsoft Edge) двойным щелчком мыши либо сочетанием клавиш `Ctrl + O` в окне браузера.

### 2. Публикация на GitHub Pages
1. Инициализируйте репозиторий и зафиксируйте файлы:
   ```bash
   git init
   git add .
   git commit -m "feat: complete Control Work #1 according to guidelines"
   git branch -M main
   ```
2. Создайте на GitHub репозиторий `kr1-html-css-shop` и свяжите с локальным проектом:
   ```bash
   git remote add origin https://github.com/Dench377/kr1-html-css-shop.git
   git push -u origin main
   ```
3. В настройках репозитория на GitHub перейдите в **Settings -> Pages**:
   - В выпадающем меню **Branch** выберите `main`, папку `/ (root)`;
   - Нажмите **Save**. Сайт станет доступен по адресу `https://Dench377.github.io/kr1-html-css-shop/`.

## Ответы на контрольные вопросы (Раздел 23 методических указаний)

1. **Почему каждая контрольная работа выполняется в отдельном репозитории?**  
   Для изолированного версионирования этапов разработки, независимого деплоя на GitHub Pages и сохранения истории развития проекта от статического сайта к динамическому SPA.
2. **Чем многостраничный сайт отличается от одностраничного?**  
   Многостраничный сайт состоит из нескольких самостоятельных HTML-документов с собственными URL, уникальными тегами `title` и `meta description`, что улучшает SEO, снижает единовременную нагрузку и логически разделяет разнородный контент (каталог, заказ, контакты).
3. **Какие страницы должны быть в КР №1?**  
   Обязательные страницы: `index.html` (главная), `catalog.html` (каталог), `product.html` (карточка товара), `order.html` (форма заявки), `contacts.html` (контакты). Дополнительно создана `about.html` (о компании).
4. **Для чего нужна единая навигация?**  
   Для обеспечения предсказуемого пользовательского опыта (UX): посетитель в любой момент понимает, на какой странице находится, и может беспрепятственно перейти в любой ключевой раздел сайта.
5. **Для чего используются якорные ссылки?**  
   Для быстрой прокрутки страницы к определенному смысловому разделу (например, `#advantages`, `#popular`, `#contacts`) по совпадению хэша URL с атрибутом `id` элемента.
6. **Почему важно использовать семантические теги?**  
   Семантические теги (`header`, `nav`, `main`, `section`, `article`, `aside`, `footer`) формируют доступное дерево документа (Accessibility Tree) для скринридеров, упрощают индексацию поисковыми роботами и делают структуру кода понятной для разработчиков.
7. **Почему на странице должен быть только один тег main?**  
   По спецификации W3C тег `<main>` обозначает уникальное центральное содержимое текущего документа. Дублирование `<main>` нарушает семантическую структуру страницы и дезориентирует программы чтения с экрана.
8. **Для чего используется тег article?**  
   Для автономных, самодостаточных фрагментов контента, которые сохраняют свой смысл даже при отделении от остального документа (карточка товара, отзыв, статья блога).
9. **Для чего нужна таблица в HTML/CSS-проекте?**  
   Для структурированного табличного представления двумерных данных (технических характеристик, сравнения комплектаций или тарифов) с использованием семантических элементов `caption`, `thead`, `tbody`, `th`, `td`.
10. **Для чего нужна форма заявки?**  
    Для сбора контактных данных пользователя, параметров заказа и обратной связи с обеспечением предварительной валидации на стороне браузера (HTML5 Form Validation).
11. **Чем CSS-модалка отличается от `<dialog>`?**  
    CSS-модалка управляется свойствами CSS (`:target` или переключение классов) без встроенного API браузера, в то время как тег `<dialog>` поддерживается браузером нативно, имеет встроенные методы `.showModal()`, `.close()` и изолированный верхний слой (Top Layer).
12. **Для чего нужны CSS-переменные?**  
    Для централизованного хранения дизайн-токенов (цветов, отступов, радиусов, шрифтов), устранения дублирования кода, упрощения поддержки и мгновенной смены темы оформления.
13. **Почему важно оформлять состояния :hover и :focus-visible?**  
    Состояние `:hover` дает визуальный отклик пользователям мыши, а `:focus-visible` критически важен для доступности пользователей клавиатуры (фокусное кольцо информирует о текущем активном элементе ввода).
14. **Для чего используется Flexbox?**  
    Для одномерного позиционирования элементов вдоль одной оси (по горизонтали или по вертикали): навигационные меню, выравнивание содержимого в шапке, кнопки, строчки цен.
15. **Для чего используется CSS Grid?**  
    Для двумерного сеточного позиционирования элементов одновременно по строкам и столбцам: сложные макеты страниц, адаптивные сетки каталога товаров, структурированные дашборды.
16. **Что такое БЭМ?**  
    Методология именования и структурирования кода (Блок, Элемент, Модификатор), обеспечивающая модульность, предсказуемость стилей, отсутствие конфликтов специфичности и удобство переиспользования компонентов.
17. **Чем блок отличается от элемента?**  
    Блок — это независимый компонент интерфейса, сохраняющий целостность в любом месте страницы (`product-card`). Элемент — это составная часть блока, которая не имеет смысла вне его контекста (`product-card__title`).
18. **Чем элемент отличается от модификатора?**  
    Элемент обозначает составную часть блока (`order-form__label`), а модификатор задает изменение внешнего вида, состояния или поведения блока либо элемента (`product-card--discount`, `button--primary`).
19. **Почему не рекомендуется стилизовать элементы через id?**  
    Селектор по `id` имеет избыточно высокую специфичность, что приводит к конфликтам каскада, усложняет переопределение стилей и препятствует повторному использованию компонентов на одной странице.
20. **Что должно быть указано в README.md?**  
    Название и тема работы, описание назначения проекта, дерево структуры файлов, перечень технологий, ссылки на GitHub Pages и репозиторий, инструкция по просмотру, описание страниц и самостоятельных доработок, ФИО и группа студента.
21. **Какие элементы проекта были доработаны самостоятельно?**  
    Добавлена 6-я страница `about.html`, реализован двухуровневый механизм модального окна, липкий боковой фильтр каталога, плавающая кнопка наверх, интерактивные блоки FAQ и отзывов, полная шкала CSS-переменных и автономная векторная графика.
22. **Почему выбранная самостоятельная доработка улучшает проект?**  
    Она приближает учебный проект к реальному промышленному интернет-магазину, демонстрирует уверенное владение передовыми инструментами CSS Grid/Flexbox, улучшает пользовательский опыт и доступность (a11y), а также закладывает идеальную основу для адаптации в КР №3 и добавления скриптов в КР №4.
